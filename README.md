## 课题：拆解一款著名小游戏

从下面三款里选一个，写一份完整的拆解案。每款都配了一篇参考文章，**动笔前先读**。

| # | 游戏 | 类型 | 参考文章 |
| --- | --- | --- | --- |
| 1 | 愤怒的小鸟 | 物理弹射 | [《愤怒的小鸟2》底层关卡设计](https://www.gameres.com/813913.html) |
| 2 | 水果忍者 | 切割反应 | [向水果忍者开发者学习如何设计游戏](https://www.gameres.com/forum/t/488739) |
| 3 | 植物大战僵尸 | 塔防 / 关卡推进 | [《植物大战僵尸》的 12 个成功秘诀](https://www.gameres.com/168727.html) |

三选一，**允许多人选同一个**，各自独立完成。

> 这三篇是参考，不是模板：它们分别从关卡、手感、设计取舍切入，读完再动笔。
> 你的作业结构仍按下面的八章来。

> 拆解是分析“它为什么好玩、怎么设计的”，不是写通关攻略。
> 不要大段复述玩法流程，重点是**结构、数值、节奏和取舍**。

## 拆解案要写什么

**不要求字数和图表数量**，但**推荐用流程图把结构画出来**——一张核心循环图，往往比三段文字更清楚。

流程图画法不限：Excalidraw、draw.io、ProcessOn、Figma 都行，导出 PNG 放进仓库的 `images/`。

| 章节 | 要回答的问题 | 推荐配图 |
| --- | --- | --- |
| 1. 游戏概览 | 类型、平台、核心卖点、目标用户、和同类比差异在哪 | 一张游戏画面 |
| 2. 核心循环 | 操作 → 反馈 → 奖励 → 再投入 | **核心循环图（推荐）** |
| 3. 关卡与难度 | 选 3 个代表性关卡，拆目标、障碍、教学、难度曲线 | 关卡结构草图或难度曲线 |
| 4. 系统与数值 | 经济、成长、解锁、分数规则；能列表就列表 | 系统关系图或数值表 |
| 5. 体验与情绪 | 首次体验、心流区间、挫败点和爽点分别在哪 | 情绪曲线（可选） |
| 6. 商业化（可选） | 原版手游的付费点、广告、买断/内购的取舍 | — |
| 7. 可借鉴与再设计 | 如果让你改，你会改哪三处，为什么 | 改法示意（可选） |
| 8. 参考资料 | 引用的文章、视频、数据来源 | — |

**第 7 章是重点**：只拆不改，说明你只是看懂了；能提出有依据的修改，才算想明白了。

## 你要做什么

### 第 1 步 · 建 GitHub 账号

1. 打开 [github.com](https://github.com) 注册
2. 用户名建议用拼音，例如 `zhangsan`
3. 记下你的用户名，后面提交要用

> 已经有账号的直接用，不用新建。

### 第 2 步 · 建自己的拆解仓库

1. GitHub 右上角 **+** → **New repository**
2. 名字：`plan-<游戏名>-<姓名拼音>`，例如 `plan-angrybirds-zhangsan`
3. 可见性：**Public 或 Private 都可以**
   - 选 Private 的话，第 3 步必须做，否则助教看不到
4. 勾选 **Add a README file**
5. 点 **Create repository**

### 第 3 步 · 把助教加为 Collaborator（必做）

1. 进入你的仓库 → **Settings**
2. 左侧 **Collaborators** → **Add people**
3. 搜索 **`Zeroink6672`**
   - 搜不到就用邮箱：`3377133365@qq.com`
4. 权限选 **Read** 即可 → **Add**

> 加完对方会收到邀请，**需要助教点接受**。提交前在 PR 里说一声“已邀请”，助教确认通过后再验收。
>
> 仓库是 Public 的也建议加，方便助教留评论。

### 第 4 步 · 写拆解案

推荐用 Markdown 写，GitHub 上能直接看。目录建议：

```
README.md            ← 拆解案入口：摘要 + 目录
01-overview.md       ← 游戏概览
02-core-loop.md      ← 核心循环
03-levels.md         ← 关卡与难度
04-systems.md        ← 系统与数值
05-experience.md     ← 体验与情绪
06-monetization.md   ← 商业化（可选）
07-redesign.md       ← 可借鉴与再设计
08-references.md     ← 参考资料
images/              ← 所有图片
```

几点要求：

- **图片放 `images/`**，用相对路径引用：`![](images/core-loop.png)`
- 图表自己画，不要直接截游戏界面当分析图（截图可以当素材，但要配说明）
- 引用别人的观点、数据，必须在第 8 章标注来源
- 正文不要整段复制攻略、百科、评测

### 第 5 步 · 自检

提交前用**无痕窗口**（或退出登录）打开你的仓库链接，确认：

- [ ] 仓库能打开（Private 的话，说明 Collaborator 已加并接受）
- [ ] README 能正常渲染，目录链接能跳
- [ ] 所有图片都能显示（没有裂图）
- [ ] 八个章节齐全，核心循环图画出来了
- [ ] 第 7 章有自己的修改提案，不是空话

### 第 6 步 · 提交

1. **Fork 本仓库**
2. 在 `submissions/` 下新建 `<学号>-<姓名拼音>.md`（模板见下）
3. Commit → Push → 开 **Pull Request** 到本仓库 `main`
4. PR 标题：`提交：<游戏名> - <姓名>`

### 第 7 步 · 返修

助教在 PR 里评论。改完在**同一个分支**继续 commit + push，PR 自动更新，不用重新开。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 助教打不开仓库 | Private 但没加 Collaborator，或邀请没接受 | Settings → Collaborators 加 `Zeroink6672`，并提醒助教接受 |
| 搜不到 `Zeroink6672` | 用户名搜索有时不稳定 | 改用邮箱 `3377133365@qq.com` |
| 图片是裂的 | 用了本地绝对路径，或图片没 push | 改成 `images/xxx.png` 相对路径，确认图片在仓库里 |
| 能给 Word / PDF 吗 | GitHub 上不能直接预览 | 统一用 Markdown + PNG |
| 可以照抄网上的评测吗 | 不允许整段复制 | 可以引用观点，但要标注来源并用自己的话重写 |
| 三个游戏都想写 | 时间不够 | 选一个写深，比写三个写浅强 |
